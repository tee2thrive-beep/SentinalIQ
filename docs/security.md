# SentinelIQ — Security Architecture & Hardening Policy

This document outlines the security policies, access controls, data handling, and automated disclaimers governing the **SentinelIQ Cyber Incident Prioritization Engine (PS-03)**.

---

## 1. CORS Hardening Policy

- By default in development, CORS permits requests from `http://localhost:3000` and `http://localhost:5173`.
- In production, wildcard CORS (`*`) is explicitly disabled. The API reads allowed origins from `SENTINELIQ_CORS_ORIGINS`.
- Allowed HTTP methods are restricted to `GET`, `POST`, `OPTIONS`.

---

## 2. Secrets & Environment Isolation

- No API keys, database credentials, or secret tokens are hard-coded in the source code or frontend bundles.
- Frontend environment variables exposed via Vite (`VITE_*`) are strictly limited to public endpoints (`VITE_API_BASE_URL`).
- All `.env` files are excluded from Git via `.gitignore`.

---

## 3. Exception Handling & Error Disclosures

- FastAPI exception handlers trap `HTTPException` and uncaught `Exception` instances.
- Internal stack traces, raw filesystem paths, database structures, or system environment variables are **never** returned in API responses.
- API errors return standardized JSON payloads: `{"error": true, "status_code": 404, "detail": "..."}`.

---

## 4. Input Validation & Parameter Bounding

- Pagination query parameters (`page`, `page_size`) are strictly bounded (`1 <= page_size <= 100`, `page >= 1`).
- Filter string inputs (e.g., `risk_level`) are validated against allowed sets (`CRITICAL`, `HIGH`, `MEDIUM`, `LOW`). Invalid inputs return `400 Bad Request`.

---

## 5. Automated Recommendation Disclaimer

> [!IMPORTANT]
> **Analyst Guidance Policy**: Recommendations generated by SentinelIQ represent policy-based guidance for SOC analysts. No containment, host isolation, user account suspension, or network reconfiguration action is executed autonomously by the engine.

---

## 6. HTTPS & Transport Security

- Production deployments behind Nginx enforce TLS 1.2/1.3 transport security.
- Security response headers (`X-Frame-Options`, `X-Content-Type-Options`, `X-XSS-Protection`) are applied at the proxy gateway.
